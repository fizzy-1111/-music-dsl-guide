How Music DSL looks in the editor

The editors draw .music text with a "reading view". Only the drawing changes — the file text stays exactly as written. This page reproduces that view with the real colours and rules.

2. Duration: lines instead of brackets

One quarter note is 1 beat. Count the lines: underline = ÷2, overline = ×2. Several lines multiply.

Function-call parentheses such as repeat(…) are not duration groups. They are never hidden and are coloured by depth.

3. When you edit: brackets come back

Put the caret in or next to a group and its brackets reappear as plain text so you can edit them; move away and they hide again. Selecting text (even the whole file) keeps the reading view.

4. Symbol legend

Pitches are digits 1–7 (C D E F G A B). The octave is a small superscript; a negative octave gets a small bold ⁻ so it is not confused with the digit.

In the editor the chromatic colour is decided by the compiler from the active key (a note that needs a sharp/flat the key does not already give). This static page cannot know the key, so it approximates: any pitch with a written accidental is drawn in that colour.

6. Switching it on and off

  • VS Code / Cursor: command Music DSL: Toggle Duration Brackets as Lines, or setting musicDsl.durationLines.enabled.
  • Web / Android editor: command palette → the duration-brackets toggle (stored as musicdsl.compactBrackets on the device).
  • Spacing: musicDsl.notationSpacing.enabled and musicDsl.notationSpacing.octaves (default −0.14 em) tighten notes and octave marks.
  • Bracket colours: musicDsl.colorBlocks and musicDsl.blockColors (default #61afef #c678dd #98c379 #e5c07b #56b6c2, five depths).
